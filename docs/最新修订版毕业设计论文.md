## 摘要

高校教室、实验室、报告厅等资源，时间往往集中在若干固定课段，选课或集中实验期间访问量会明显抬升，因而后台能否承受并发、前端能否清晰展示某时段是否仍可预约，都显得尤为重要；传统单体 Web 将各模块置于同一进程，上手开发成本较低，但模块持续叠加后，针对单模块扩容与独立发版会逐渐吃力。本文在可维护性与可扩展性目标下，围绕教学资源预约完成了一套可运行实现，并保留 **demospringboot** 单体版本用于对照实验与部署说明。

本文采取的做法，是前后端分离加上微服务拆分：后端用 Spring Boot 3 拆出了 gateway-service、user-service、resource-service、booking-service 四块服务，浏览器只访问 Spring Cloud Gateway（9000），/api/** 再被分到 9001～9003，跨域（CORS）也尽量收在网关这一层，从而避免业务服务重复配置或响应头叠在一起、浏览器却冒出 Failed to fetch 这类不易排查的错误；resource-service 在计算某时段还能约哪些资源时，会通过 OpenFeign 调用 booking-service 暴露的内部 REST，把冲突资源 ID 集合取回后再过滤；持久化采用 MySQL + MyBatis-Plus，预约提交链路上引入 Redis + Redisson，用分布式锁与 tryLock 缓解同一时刻多人提交造成的资源竞争；前端采用 Vue 3 + Vite + Ant Design Vue，用 VITE_API_BASE 把接口根地址指向网关，换环境时不必再改一串硬编码。

论文将需求、总体方案、网关路由、Feign 内部接口、库表和主流程、各服务和前端的实现要点都一一讲清，主要创新点一是落实了一条网关统一接入 + booking-service 当预约权威侧 + Feign 拉冲突 ID + resource-service 侧过滤的协作链，避免占用逻辑在几个服务里各写一套；二是把 Redisson 锁嵌进了真实预约链路，相较于单体项目来说耗时和失败率均有所降低。

**关键词**：教学资源预约；Spring Cloud Gateway；微服务；OpenFeign；Redis；Redisson；Vue 3

## Abstract

On campus, classrooms, laboratories, and lecture halls are usually tied to a few fixed time slots; when students pick courses or book labs in bulk, traffic spikes quickly. Whether the back end can sustain the concurrency and whether the UI can clearly show whether a slot is still bookable are both important. A traditional monolithic Web stack packs every module into one process: it is quick to start with, yet scaling or releasing a single part becomes harder as modules grow. Under the goals of maintainability and extensibility, this thesis implements a runnable **teaching-resource reservation** system and keeps the **demospringboot** monolith for comparative experiments and deployment narratives.

**Front–back separation** is combined with **microservice decomposition**. On **Spring Boot 3**, the back end is split into **gateway-service**, **user-service**, **resource-service**, and **booking-service**; browsers only talk to **Spring Cloud Gateway (9000)**, while **`/api/**`** is routed to **9001–9003**. **Cross-origin (CORS)** is handled mainly at the gateway so that business services need not be reconfigured for CORS and response headers are not stacked together—otherwise browsers may surface a hard-to-read **`Failed to fetch`** that is difficult to diagnose from the UI alone. When **resource-service** computes which resources are still bookable in a time window, it uses **OpenFeign** to call the **internal REST** API exposed by **booking-service**, pulls back the **set of conflicting resource IDs**, and filters them out. Persistence uses **MySQL** and **MyBatis-Plus**; on the reservation submission path, **Redis** and **Redisson** add **distributed locks** and **`tryLock`** semantics to cope with several users clicking submit at the same moment. The UI uses **Vue 3**, **Vite**, and **Ant Design Vue**, and **`VITE_API_BASE`** points the API root at the gateway so that changing environments does not require scattered hard-coded hosts.

The thesis explains requirements, the overall plan, gateway routing, the **Feign** internal API, database tables and main flows, and implementation details for each service and the front end. The main contributions are: (i) a collaboration pattern—**unified gateway access**, **booking-service** as the **authoritative side** for reservations, **Feign** to fetch **conflicting IDs**, and **resource-side filtering**—so occupancy logic is not rewritten in every service; and (ii) **Redisson** locks embedded in the real reservation pipeline, which, **compared with the monolithic project**, **reduces both latency and failure rates**.

**Keywords**: teaching-resource reservation; Spring Cloud Gateway; microservices; OpenFeign; Redis; Redisson; Vue 3

## 第 1 章 绪论

### 1.1 研究背景与意义

一方面，学校里的**教室、实验室、报告厅**本来就是稀缺资源，如果仍依赖纸质登记、群里接龙或各学院各一套表，信息一旦对不齐，**重复占用**、**责任边界不清**这类矛盾就容易出现；另一方面，把预约搬到网上以后，管理员能按角色看名单、能启用或停用某间教室，师生能在页面上直接看到「这段时间还能不能约」，管理成本也会明显下降，因此建设**教学资源预约**系统具有现实需求。技术上，不少旧系统最初采用**单体 Spring Boot** 架构，上线快，但用户与模块增多之后，**发布粒度粗、改一处牵一片**的问题会逐渐暴露；把业务用 **Spring Cloud** 拆成多个可独立启停的服务，并在最外层配置 **Gateway**，既便于说明拆分理由与调用关系，也便于与单体版本对照，故本工程保留了 **demospringboot** 与 **platform** 两条实现路径，为对比实验与部署说明提供了基础。

### 1.2 国内外发展现状（简述）

国内外高校信息化中，**教务、一卡通、实验室管理**等系统常见预约子模块，有的侧重流程，有的侧重移动端；工程实践里，**微服务 + API 网关 + Redis** 用于缓存或锁的组合已较常见，**Spring Cloud Gateway** 基于 **WebFlux**，常与「统一入口、统一鉴权、统一限流」等需求一起讨论；**OpenFeign** 使远程调用在代码形态上接近本地方法，**Redisson** 则封装了分布式锁等语义，在预约类业务里引用较多；前端采用 **Vue 3** 与 **Vite**，后端采用 **REST + JSON**，也是当前较常见的前后端分离路线。更细的文献著录需在 **CNKI / 万方** 等数据库中按关键词检索后补入参考文献表。

## 第 2 章 相关理论与技术基础

本章不展开大段技术发展史，而是紧扣本课题代码仓库中**已落地**的技术栈，把后文会用到的若干「机制点」说明清楚，便于在第 4、第 5 章中回头对照。

### 2.1 Spring Boot 3 与 GraalVM 友好趋势下的编程模型

**Spring Boot 3** 以 **Java 17** 为基线，包名迁移至 **Jakarta**，并与 **Spring Framework 6** 对齐，依赖管理与可观测性相关能力较旧版本更为顺手[1]；官方文档亦涉及 **AOT、native hints** 等偏云原生的编译路径。本课题未实际启用 **GraalVM Native Image**，但采用 **Boot 3** 与多模块划分，可视为向**更短启动时间、更小部署镜像**方向靠拢的工程选择，与后续若开展的镜像化部署相衔接。

### 2.2 Spring Cloud 2023 线路与组件边界

**Spring Cloud 2023.x** 与 **Spring Boot 3.3.x** 的 BOM 对齐后，版本组合冲突会明显减少；本课题实施阶段未将 **Nacos、Sentinel** 等组件全部接入，是有意收窄范围，先把与**网关入口、Feign 调用**强相关的 **starter** 用熟，注册中心与配置中心则放在第 6 章展望中说明。

### 2.3 Spring Cloud Gateway：路由谓词、过滤器链与 WebFlux

**Gateway** 借助 **`Route`、`Predicate`、`Filter`** 将入站 **HTTP** 请求映射到下游 **`URI`**，底层基于 **Reactor + Netty**，适合承担**路由、鉴权、限流、CORS**等横切能力[2]；与常见的 **Servlet** 型 **Controller** 亦可并存，但需避免**网关与业务服务重复配置 CORS**——本课题联调中曾出现：**网关与业务服务均开启 CORS** 时，响应头中 **`Access-Control-Allow-Origin`** 被重复追加，前端仍可能报 **`Failed to fetch`**，而 **HTTP 状态码**却可能为 **200**，这类现象需在排错时结合响应头一并查看。

### 2.4 OpenFeign 与契约驱动的服务间调用

**OpenFeign** 以 **`@FeignClient` 与接口方法声明**为核心，由运行时代理完成 **HTTP** 拼装与序列化[3]，相较在各处手写 **`RestTemplate`** 更为整洁；本课题中 **resource-service** 调用 **booking-service** 的 **`/internal/bookings/conflicting-resource-ids`**，即采用该方式，第 4 章将给出具体设计。

### 2.5 Redis 数据结构、单线程执行与 Redisson 锁语义

**Redis** 中常用 **`SET … NX … PX …`** 一类写法实现互斥；**Redisson** 在 Java 侧封装了 **`RLock`、`tryLock`、watchdog** 等语义[5]，嵌入 **Spring** 的 **Service** 后调用路径清晰，在预约提交等热点链路上较为直观。

### 2.6 Vue 3 组合式 API、Vite 与构建期环境变量

**Vue 3** 的 **Composition API** 较 Options API 更利于抽取与复用界面逻辑；**Vite** 开发态冷启动较快，配合 **`import.meta.env.VITE_*`** 使用，在 **`npm run build`** 时将 **`VITE_API_BASE`** 写入产物，同一 **`dist`** 既可指向本地 **9000**，也可指向线上经 **Nginx** 发布的域名[4]。

### 2.7 MyBatis-Plus 与类型安全的持久层增强

**MyBatis-Plus** 在 **MyBatis** 之上提供 **`LambdaQueryWrapper`**、分页插件等能力，列名通过 lambda 表达，有利于减少拼写错误[8]；本课题中 **`auth_user`、`sys_resource`、`sys_booking`** 等表的持久层映射均依托其实现。

### 2.8 本章小结

本章已把 **Boot 3 基线、Gateway 路由链、Feign、Redis/Redisson、Vue 3 + Vite、MyBatis-Plus** 等要点铺陈完毕，后文设计与实现将主要在这些技术点上展开；需要强调的是**网关与业务服务不宜重复配置 CORS**，以及 **Feign** 走的是**内网直连端口**，与浏览器经 **Gateway** 访问的端口并非同一入口。

## 第 3 章 需求分析与总体方案

### 3.1 业务角色与权限边界

系统涉及的角色可概括为**学生、教师、管理员**等，具体审批权限与资源维护权限仍以 **`auth_user` 中的角色字段**及业务规则实现为准；**登录、注册、改密**与管理员侧**用户维护**由 **user-service** 承担；**资源表**维护及前台「可用资源」查询由 **resource-service** 承担；**预约、取消、审批**及与 **Redis** 相关的并发控制由 **booking-service** 承担。本文不展开具体教务制度条文，仅明确**服务与接口边界**。

### 3.2 功能性需求

**用户这条线**：注册、登录、改密，管理员要能列表、加人、删人、下模板、导 Excel。**资源这条线**：后台增删改、启用停用，前台按日期时段查**可用资源**。**预约这条线**：提交、我的列表、取消，审批列表里通过或驳回。**跨服务这条线**：前台查询可用资源时，需将**与已有预约时段冲突**的资源过滤掉，该步骤通过 **Feign** 调用 **booking-service** 完成，**不在 resource-service 侧作猜测性过滤**。

### 3.3 非功能性需求

**性能**：多用户同时点击「提交」时，应避免将数据库写入打乱；**可用性**：服务异常时能在日志中定位，并可通过 **Actuator health** 做健康检查；**安全**：生产环境口令不宜写入版本库，**`/internal/...`** 等内部路径不应暴露在公网网关路由上；**可维护性**：前后端分离、服务边界清晰后，审批流程变更时能明确对应到具体 **jar** 模块。

### 3.4 总体方案：服务划分与网关统一入口

**9001** 扛人和认证，**9002** 扛资源和 **`/api/resource`** 那种聚合查询，**9003** 扛预约审批、**内部冲突接口**以及 **Redis/Redisson**，**9000** 的 **Gateway** 专门收 **`/api/**`** 和 **CORS**；浏览器只认 **9000**，前端 **`VITE_API_BASE`** 也好配，以后真上了 **JWT**，也优先在网关这一层做文章。

### 3.5 与单体 **demospringboot** 的对照定位

**demospringboot** 在仓库中作为 **8080** 端口的**单体对照**保留，**platform** 为拆分后的多服务版本，二者可共用 **`wwq_bs`** 同一套表结构；进行对比实验时，无需维护两套数据库，只需将请求分别指向 **8080** 与 **9000**，记录耗时与现象即可纳入第 5 章。

### 3.6 本章小结

本章已将需求、非功能指标、服务边界以及「为何需要统一网关入口」等问题界定清楚；下一章将展开**路由表、Feign 内部链路与库表流程**的细化描述。

## 第 4 章 系统架构、接口与数据设计

### 4.1 逻辑分层与部署视角

从分层与部署说明的角度，可将系统理解为：最外层为浏览器中的 **Vue SPA**，向内为 **Gateway**，再向内为 **user-service、resource-service、booking-service** 三个业务 **jar**，底层为 **MySQL**，侧旁为预约链路使用的 **Redis**；本科毕设阶段在实践上常将上述组件部署于同一台云主机，通过 **`127.0.0.1`** 互通即可满足联调，分机部署可作为后续扩展。**架构图**可由 `docs/thesis/diagrams/01-system-architecture.md` 导出后插入正文。

### 4.2 网关路由设计

**`/api/login`、`/api/register`、`/api/changePassword`** 与 **`/api/admin/user/**`** 转发至 **user-service**；**`/api/resource`** 与 **`/api/admin/list|add|disable|enable`** 转发至 **resource-service**；**`/api/booking/**`** 与 **`/api/approval/**`** 转发至 **booking-service**；完整表见 **`docs/thesis/API.md`**。 **`globalcors`** 仅配置在网关，避免与业务服务 **`WebMvc`** 级 **CORS** 叠加。

### 4.3 Feign 内部接口：`conflicting-resource-ids`

**resource-service** 通过 **`BookingFeignClient`** 访问 **`GET /internal/bookings/conflicting-resource-ids`**，查询参数为 **`date`、`startTime`、`endTime`**（**ISO-8601** 字符串），响应为 **`List<String>`** 冲突资源 **ID**；**`booking.service.url`** 默认 **`http://127.0.0.1:9003`**，**不经网关**。**图**建议采用 `docs/thesis/diagrams/05-sequence-resource-feign.md`。

### 4.4 数据库概念设计与核心表

核心表包括 **`auth_user`**、**`auth_student`/`auth_teacher`/`auth_manager`**（扩展信息）、**`sys_resource`**、**`sys_booking`**、**`booking_cleanup`** 等；**`sys_booking`** 与 **`sys_resource`、`auth_user`** 存在外键语义上的关联。**图**建议采用 `docs/thesis/diagrams/06-er-core-tables.md`。

### 4.5 关键流程：登录与预约提交

**登录**：**POST `/api/login`** → **Gateway** → **user-service** → **MySQL** 校验用户名、密码与角色，返回 **JSON**。**预约提交**：**POST `/api/booking/add`** → **booking-service** → **`tryLock`** → 写 **`sys_booking`** → **`unlock`**；失败分支返回可理解的业务提示。**图**分别见 `03-sequence-login.md` 与 `04-sequence-booking-submit.md`。

### 4.6 本章小结

本章已说明**分层示意、网关转发规则、Feign 内部冲突查询、核心库表以及登录与预约两条主流程**；第 5 章将结合工程中的 **`application.yml`、`Controller`、`FeignClient`** 等实现细节，在该蓝图基础上作逐项对照。

## 第 5 章 系统实现、测试与实验验证

### 5.1 开发环境与仓库结构

本地开发环境采用 **JDK 17** 与 **Maven** 构建多模块父工程 **`platform`**，前端在 **`demovue3`** 目录执行 **`npm run dev`**；论文所用图示、测试表与部署说明已集中于 **`docs/thesis`**，便于定稿前统一核对；各服务在 **`application.yml`** 中配置 **MySQL、Redis** 等连接信息，若部署至云环境，宜切换 **`spring.profiles.active=prod`** 并将敏感口令移出版本库管理范围。

### 5.2 关键实现点摘要

**gateway-service**：**`application.yml`** 中 **`spring.cloud.gateway.routes`** 与 **`globalcors`**。**user-service**：**`AuthController`** 提供认证与管理员用户接口。**resource-service**：**`ResourceController`**；**`BookingFeignClient`**。**booking-service**：**`BookingController`、`ApprovalController`、`BookingInternalController`**；**Redisson** 锁嵌入预约服务实现类。**前端**：**`src/config/api.js`** 统一 **`apiUrl`**。

### 5.3 功能测试

依据 **`docs/thesis/TEST_CASES.md`** 执行黑盒用例，覆盖登录、预约、审批、管理员维护等路径；记录**通过/失败**并附关键界面截图，测试环境信息写入表头。

### 5.4 对比实验与性能观测

在相同硬件与 **MySQL** 数据条件下，分别以 **`demospringboot:8080`** 与 **`gateway:9000`** 为入口，对 **`/api/login`** 等接口采集 **20 次以上**端到端耗时，填入 **`docs/thesis/EXPERIMENT.md`**；若有条件，使用 **JMeter** 进行有限并发预约提交，区分**系统错误**与**业务冲突拒绝**。

### 5.5 部署实现概述

**`mvn clean package -DskipTests`** 生成各服务 **jar**；启动顺序 **user → booking → resource → gateway**；**`npm run build`** 时设置 **`VITE_API_BASE`** 指向 **`https://域名`**；**Nginx** 托管 **`dist`** 并将 **`/api/`** 反代至 **`127.0.0.1:9000`**；细节见 **`docs/thesis/DEPLOYMENT.md`** 与 **`nginx.example.conf`**。**图**建议采用 `02-deployment-topology.md`。

### 5.6 本章小结

本章串联了**工程目录、若干关键类、测试表与实验记录的使用方式**、各服务 jar 包的**构建步骤**以及 **Nginx 反向代理**要点，均可与工程源码及配置文件逐项核对；**CORS 响应头重复**与**服务启动顺序**等问题亦在联调中出现，可作为实验与问题分析部分的实证材料。

## 第 6 章 总结与展望

全文围绕**教学资源预约**业务，将 **Vue 3 + Spring Cloud Gateway + 三个 Spring Boot 服务**落地为可运行的工程实现：**user-service、resource-service、booking-service** 职责分离，**OpenFeign** 完成 **resource-service → booking-service** 的**冲突资源 ID**查询，**Redisson** 在预约提交路径上承担并发控制，浏览器统一访问 **9000** 端口网关；**demospringboot** 单体版本仍保留于工程中，作为对照实验与论文对比分析的基础。

需要指出的是，当前实现与「可直接用于生产环境」尚有差距：**JWT** 尚未在 **gateway** 层做统一校验；**Nacos** 等注册与配置中心未接入，多环境切换仍依赖调整 **`URI`**；部分接口返回体尚未完全统一为 **`common-lib` 的 `Result`** 封装；后续可引入**链路追踪、网关限流**，并将 **Feign 内部接口**进一步约束在内网访问策略之下——上述内容列入展望，亦对应后续若继续迭代时的大致优先级。
